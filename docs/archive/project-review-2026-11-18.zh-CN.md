### 维护与测试缺口

- **P2，Web 状态与线程句柄混用。** [状态接口](../../app.py#L1864) 直接序列化整个任务字典。测试客户端空闲返回 200，放入真实线程句柄模拟运行态后返回 500。[新建](../../app.py#L1515)和[恢复](../../app.py#L1700)也都先检查空闲，完成耗时准备后才写入占用，中间没有互斥。用锁保证只接收一个任务，状态接口只返回公开字段；回收时核对任务 ID。分别验收在途查询和两次同时提交。
- **P2，旧版 Fast 恢复会被一个无用的帧率参数打断。** [迁移调用](../../src/depth_surge_3d/processing/orchestration/pipeline_orchestrator.py#L437) 对合法的 `None` 或 `"original"` 调用 `float()`，而[下游立即丢弃该参数](../../src/depth_surge_3d/processing/orchestration/pipeline_orchestrator.py#L939)。复用仓库已有迁移测试、只改变该设置，两种原帧率表示都到不了后处理，数值 24 可以。删去无用参数，补这两种旧配置的回归。
- **P2，有 10 个编排测试实际上没跑。** [第一个遗漏用例](../../tests/unit/test_pipeline_orchestrator.py#L1561)及后续 9 个均缩进在另一个测试函数里。涉及模型卸载、VDPP 顺序、输出失败等。语法树扫描得到 10 个；用 pytest 按其中 3 个名字单独收集，结果是 0 个。移回正确测试类并核对收集清单，再处理新增暴露的失败。
- **CI 的格式问题会屏蔽功能信号，测试环境也没有安装项目命令。** 本机用 CI 固定的 Black 25.1.0 检查，25 个文件需要格式化。[功能测试依赖代码风格任务](../../.github/workflows/ci.yml#L40)，因而这个门槛失败会让主 CI 的功能测试跳过。即使通过，[测试作业也只安装依赖](../../.github/workflows/ci.yml#L60)和编译扩展，没有安装声明命令行入口的项目本身；[打包用例](../../tests/unit/test_moge2_docs.py#L351)却明确需要该命令。保留两项合并检查，但让它们独立执行；直接安装本次构建的包测试，不靠源码目录或开发机残留的命令。格式整理单独提交。

### 第三批：Linux 发布与中断恢复

- **修前实证：** Linux 上一次已经成功的 FFmpeg 编码，在成片换名后中断，删除输入 PNG 再恢复，旧实现报错「没有输入帧」；另一组保留输入帧，把目标换为字节相同的另一个 MP4，旧实现竟重新编码并覆盖它。
- **修复：** 文件帧编码在改动成片名称之前，将视频的文件身份、SHA-256、字节数、输入清单指纹与实际编码参数同步到现有的预留空间。恢复只推进剩余发布步骤。流式任务沿用其原有输出凭据；CLI 在持有作业锁时先恢复发布，不必重新加载深度模型。普通发布不再把已存在的路径视为覆盖授权。先前版本已完成的清单仍可验证；旧文件帧任务若中断时尚无持久凭据，会保留成片而不是猜测归属。

## 深度交互

用户要的是可播放、片段正确、耗时可接受的 3D 成片。优化目标应是**从选定素材到获得合格成片的时间**，而不是某个内核的耗时或一次“处理成功”的返回值。

1. **先把正确性变成发布条件。** 用短合成素材固定三组行为：保留两种分数帧率、24→60 且音画时长不变、同目录切换等长但不同颜色的片段。CLI 与 Web 走同一套时序和缓存规则。临时规避比错误成功好：未实现的插帧应明确告知用户。
2. **修入口，不重写流水线。** 收紧 Web 默认权限，修任务生命周期，把安装命令放进干净环境冒烟测试。复用已有发布事务和作业锁；兼容策略是让旧作业继续读取、只重建无法证明可复用的阶段，而不是改写历史清单。
3. **正确以后再找最贵的一步。** 对同一段有声素材分别记录冷启动、热运行和恢复的总耗时、各阶段耗时、峰值显存和临时磁盘占用。优先验证两个可省的工作：上传时[同步转整条 FLAC](../../app.py#L1443)，尽管[编码端已支持原视频音轨](../../src/depth_surge_3d/processing/video/final_audio.py#L405)；Web 恢复在[请求内](../../app.py#L1753)和[后台持锁后](../../app.py#L1151)都做完整阶段审查。前者可按需生成并原子发布，后者可把 UI 的进度提示与持锁后的正式校验分开。不要复用锁外校验结论代替正式校验。
4. **不要把单阶段提速当成成片提速。** [工作区已有 360 帧对照记录](../ARCHITECTURE.md#L1231)：最终化阶段中位数从 25.571 秒降到 21.554 秒，但整次处理从 323.981 秒变为 332.539 秒，其他阶段也有波动。这是仓库历史记录，不是本次新跑的基准，既不证明整片变快，也不足以认定回退。后续性能改动应在同素材交替对照、解码画面和音轨通过检查后，再根据总耗时与波动作决定。
